# 弹幕悬浮窗 (danmaku overlay)

一个透明的置顶窗口，把当前会话正在做的事变成一颗颗气泡：调用了什么工具、改了哪个文件、
这一轮是否结束。它是**纯展示面**，没有任何标题栏或按钮 —— 所有控制都在 DSH 会话页标题旁边
的「弹幕」按钮上。

```
pythonw.exe danmaku_panel.pyw --url http://127.0.0.1:<port> --session <sessionId>
```

---

## 为什么不直接用 Tk 的透明度

Tk 只能对整个窗口设一个 alpha（`SetLayeredWindowAttributes`），把背景调淡的同时气泡也会跟着变淡。
需求是「背景非常淡、气泡完全不透明」，这需要**逐像素 alpha**：把画面画进一张 32 位
premultiplied ARGB 位图，再交给 `UpdateLayeredWindow`。Tk 拿不到自己画出来的像素，所以
`layered_window.py` 自己持有 DIB，用 GDI 在上面画，然后整块交给 Windows。

---

## 三个踩过的坑

这三个都是「代码看起来完全正确、效果完全不对」的类型，记下来免得下次再踩。

### 1. GDI 根本不会写 alpha 通道

**这是气泡一直是半透明的真正原因。**

在 32 位 DIB 上，`CreateSolidBrush` + `RoundRect` 会写入 B、G、R 三个通道，
**第四个字节原封不动**；`DrawTextW` 同理。也就是说：

1. `fill()` 把整面刷成白色、alpha=60；
2. 在上面画气泡，颜色对了、形状对了、代码也对了；
3. 但气泡那几个像素的 alpha **仍然是 60**，文字甚至还是 0。

结果就是气泡看起来「颜色对但是透明的」，文字像是印在玻璃上。这不是混合参数写错了，
改任何窗口样式都没用 —— alpha 必须自己显式写进去，见 `LayeredCanvas.force_opaque()`。

顺序很重要：先画形状和文字，**最后**把这块矩形的 alpha 抬到 255。
反过来的话，`fill()` 会把刚写好的 alpha 又刷回去。

整块矩形而非沿着圆角描边，是因为气泡都画在纯色背景上，把外接矩形全部设为不透明
不会影响形状之外的内容，而窗口 region 会先把圆角切掉再交给合成器。

### 2. 透明 ≠ 点得到下面的东西

`WS_EX_LAYERED` 的窗口**看起来**透明，但它依然拥有整个矩形区域。
没有 region 的话，气泡之间那些「透明」的缝隙照样会吃掉鼠标点击 ——
一个 360×520 的窗口压在屏幕右下角，就是一块 360×520 的禁区。

`SetWindowRgn` 把窗口裁剪成「所有气泡的并集」：缝隙根本不属于这个窗口，
点击直接落到后面的东西上，而气泡本身依然可点。这才是悬浮窗能用的关键。

（之前三次「卡死」的真正原因是：`clickThrough: false` + 400×640 的窗口压在屏幕正中 + 没有 region。
`clickThrough` 只是没有 region 时的权宜之计，不是解法本身。）

### 3. 窗口跟着内容收缩

固定高度的窗口会留下大片半透明白色矩形，压住后面的东西又什么都不显示。
所以每加一颗气泡都重算一次高度，并且**不超过 `maxHeight`**（默认 520）。
栈是从底部往上堆的，所以高度变化不会让气泡移动，只是上方的空白出现或消失，
右下角始终钉住，变高是往上长而不是掉出屏幕。

启动时先测量再建窗口：如果先开一个大的再缩小，每次启动都会闪一下空窗口。

## 看得见 / 点得到 / 停得掉

悬浮窗没有关闭按钮，所以每一件事都得能从外面做。

```powershell
# 它现在在干什么？（exit 0 = 在跑，1 = 已停，2 = 从没启动过）
python.exe danmaku_panel.pyw --status

# 关掉它（按命令行匹配，绝不按进程名）
powershell -NoProfile -File stop-panel.ps1
```

`--status` 的存活判断用的是**状态文件的新旧**，不是 `os.kill(pid, 0)`。
后者在 Windows 上是错的：只要 PID 存在就返回成功，而被回收的 PID 也存在 ——
这导致过一次「关闭成功但按钮还说在跑」。

进程退出会留下记录，所以「正常停掉」和「崩了」可以区分：

| 文件 | 含义 |
| --- | --- |
| `.panel-startup.log` | 每次启动时的几何信息、region、气泡列表 |
| `.panel-status.json` | 每 5 秒重写一次；`ingested` 是收到的 SSE 事件数，涨就说明流还活着 |
| `.panel-done.json` | 正常退出时写入，带原因 |

## 诊断工具

窗口自己查不了（layered + topmost + 置顶，从外部枚举要么看不见要么直接卡死），
所以诊断都走「进程自己报告」这条路。

| 文件 | 用途 |
| --- | --- |
| `probe_alpha.pyw` | 列出匹配的窗口（含 PID、可见性）。`--printwindow` 可选，**会卡，不要随便加** |
| `compare_render.pyw` | 画一颗气泡，对比「绘制缓冲」和「屏幕截图」，用来区分「画错了」和「Windows 混合得不一样」 |

`probe_alpha.pyw` 的 `BitBlt` 路径读 layered 窗口的 DC 只会得到全 0；
`PrintWindow` 能读到内容，但它是跨进程同步请求，目标忙的时候没有超时，会挂住。

## 从 DSH 会话页控制它

会话标题旁边的「弹幕」按钮走的是 Host 插件，它和面板之间没有 IPC 通道，
全靠**面板自己写的状态文件**：进程每 5 秒重写一次 `.panel-status.json`，
`--status` 把它变成一行字加一个退出码（0 在跑 / 1 已停 / 2 没启动过）。

按钮不去记「我开过没有」。一个 Map 只知道自己开的那些，从终端开的面板、
上一次 Host 重启之前开的面板都会被当成「没开」，然后按钮就会叠第二个窗口上去。

### 三个必须用对的地方

写这段的时候踩了三个坑，都是「命令看起来没问题、结果什么都没有」的类型：

**1. 探测用 `python.exe`，启动才用 `pythonw.exe`。**

`pythonw.exe` 是 GUI 子系统程序，这类程序没有控制台。给它一根 stdout 管道，
Windows 不是接上去，而是**直接丢掉**。实测连续三次：同一条 `--status`，
`pythonw` 返回退出码 0 加一个空字符串，`python` 每次都返回完整那一行。
所以探测拿不到答案，按钮一直显示「已关闭」，而面板其实开着。
启动仍然用 `pythonw`，否则悬浮窗后面会闪一个黑框。

**2. 启动走 `subprocess.spawn`，探测走 `ctx.shell`，不能互换。**

`ctx.shell` 在命令结束时**会连带杀掉整棵进程树**。用它 `Start-Process` 起的
面板活不过几秒 —— 而且死得很安静：面板已经把启动日志写出来了，
所以看起来像「启动就崩」，其实是「被杀了」。同一个命令两边都试过：
走 `ctx.shell` 每次都消失，走我自己的 shell 十秒后还在。

反过来，探测只能用 `ctx.shell`，因为只有它的结果带 stdout —— 入口是
`execute(spec)` 拿活句柄，再 `await handle.result()` 拿 `stdout` / `exitCode`。
`subprocess` 的完成结果无论 `stdio` 怎么写都只有 `{ exitCode, signal }`。
探测本身不启动任何东西，所以进程树被杀这件事在这里没有代价。

**3. `ctx.shell` 在这台机器上是 PowerShell，不是 bash。**

PowerShell 会把**开头的引号字符串当成字符串字面量**，所以给程序名加引号会直接报
`Unexpected token` 并返回 1。程序名必须裸写，只有参数加引号。

启动还要等：面板要先把回填数据拉回来、画一帧，才会写第一个状态文件。
等太短就会把一个正常启动的面板报成「没起来」。

## 设置

`settings.json` 由进程自己读写，DSH 那边的按钮不需要 IPC 通道就能影响它。
文件改动会被监听（按 mtime），1 秒内生效。

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `alpha` | 60 | 只有背景，气泡恒为 255 |
| `width` | 360 | |
| `height` | 240 | 只是「还没有内容时」的初始高度，之后自动收缩 |
| `maxHeight` | 520 | 收缩上限 |
| `x` / `y` | `null` | 留空则自动放在工作区右下角 |
| `clickThrough` | `false` | 有 region 之后不需要开；开了气泡就点不动 |
| `maxBubbles` | 6 | 同时可见的气泡数 |
| `backfillBubbles` | 3 | 启动时回填几条，**故意很小**：整个会话回放出来是一堵没用的历史墙 |
| `maxBubbleWidth` | 300 | 窄一点，让气泡通常只有一行 |
| `idleExitSeconds` | 900 | 这么久没事件就自己退出，免得留下一个没人管的窗口 |

---

## 交互

- **点气泡** → 开一个真正的 Tk 窗口显示完整内容（在后台线程里开，
  否则它自己的事件循环会挡住后面所有气泡的读取）。
  summary 气泡的 `detail` 就是完整回复。
- **不点** → 什么都不用管，窗口会自己收缩、自己退场。

气泡右对齐、宽度跟着文字长度自适应，最长不超过 `maxBubbleWidth`。
